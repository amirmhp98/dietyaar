# Design scope — pages, data, actions, journeys

Derived from product-spec.md v1.8 (improvement plan phases B–D, decisions 022–025). This file fixes _what_ each screen contains. design.md decides how it looks (its "Product UI" section names the surfaces, glyphs and icon actions the screens below assume). Anything here that the spec does not define is a gap to resolve in the spec first.

Navigation: bottom bar with **History · Today · My plan** (Today in the middle) on phones; on wider screens the same three tabs sit inside the one top bar. The top bar carries the page title (phones) and a profile button (top end) to Settings. A floating **Log meal** pill (icon + word, the one filled emerald on the viewport) sits above the tabs on all three tabs; Meal details and the plan flows (Add your plan, Review your plan) hide it because they carry their own primary action.

## Shared components

Meal composer · Meal review · Plan slot row · Score card (+ Why this score) · Nutrition details · Completeness checkbox · Reflection card · Difference chip (portion / order / time / added item) · Name label (the name as the user wrote it, in `<bdi>`; the English label is never rendered) · Item amount ("2 × سیب", "150 g · مرغ", "≈ 180 g each") · Slot window ("12:00–15:30", "≈ …" when assumed) · Import status banner · AI notice sheet · Expand/collapse (one pattern everywhere).

They are built on the Product UI primitives of design.md (decision 025): Surface (hero / list / note) · SectionHeader (icon + title) · StatusGlyph and BandGlyph · IconAction (44 px, `aria-label`; 36 px dense inside editors) · Illustration · ScoreNumeral · MeterBar.

These names match product-spec.md section 12 and are the names to use in code (`src/components/product/`).

Design must verify: Persian and Arabic names inside English copy and beside Western digits in every component listed above, in both themes, with bidirectional isolation so punctuation and numbers do not flip.

## Out of design scope (V1)
