# Pilot phone checklist (improvement plan E4)

The owner's walkthrough on real phones before anyone is invited: **iOS Safari** and **Android
Chrome**, each in **light** and **dark**. Every cell is green before users sign up. Copy below is
quoted from `src/messages/`; if a screen reads differently, that is a finding.

## Before you start

- **URL:** `https://<staging-or-production-host>/` (fill in). Confirm `PHOTO_LOGGING_ENABLED=true`
  on that target, otherwise steps 21–23 have no photo buttons.
- **Account:** a fresh username per platform (e.g. `pilot_ios`, `pilot_android`), password of your
  choice. There is no recovery: write it down.
- **Plan text:** the owner's Persian reference menu plan (five slots, options per slot). Have it in
  the phone's clipboard.
- **A meal photo** in the gallery, and something to photograph.
- **Themes:** run the light pass first. For the dark pass set Settings › Preferences › Appearance to
  **Dark** (step 27) and repeat the steps whose row has a dark cell; Appearance **System** + the OS
  in dark mode must give the same result.
- Mark a cell ✓ when the expectation holds, ✗ with a note otherwise; leave it blank if not reached.

## Report

Every ✗ becomes a beads issue from the repo, one per finding:

```bash
bd create --title="Pilot: step <n> <what failed> on <iOS|Android> <light|dark>" \
  --description="<what you did, what you saw, screenshot name, phone model, OS and browser version>" \
  --type=bug --priority=1
```

Keep screenshots in a folder named `pilot-<date>-<platform>-<theme>/` outside the repo; name each
file by the step number. When every cell is ✓ on both phones and both themes, note the date and
the build SHA here and in `docs/runbook.md`, and invite the first users.
